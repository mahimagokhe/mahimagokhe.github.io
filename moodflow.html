MoodFlow

An emotion analytics portal that turns quick daily check-ins into a private, useful picture of emotional patterns over time.

HTML · CSS · JavaScriptIndexedDBSVG data visualizationResponsive UX
The product challenge

Mood tracking should feel as easy as a two-minute check-in, but still give people meaningful context when they return. The experience needed a low-friction entry flow, durable local persistence, and visual feedback without a backend dependency.

What I built

MoodFlow combines an expressive entry surface with a compact analytics dashboard. Users choose an emotion, set intensity from 1–10, add a reflection, and immediately see the entry reflected in their personal dashboard.

Fast capture

Eight emotion choices, an intensity slider, and an optional note keep the primary action focused and approachable.

Time-based insight

Interactive trend views aggregate intensity by day, hour, or minute so the same data can support reflection at different scales.

Personal analytics

Average intensity, frequent mood, streak, mood mix, and recent reflections turn raw entries into readable signals.

Private persistence

IndexedDB stores entries locally in the browser, with migration from the original localStorage format and a fallback for older environments.

Frontend engineering decisions

  • Separated storage concerns into database open, read, write, migration, and fallback paths so the UI can load asynchronously without losing existing data.
  • Used derived rendering functions for statistics, SVG charts, distribution, recent entries, and responsive empty states.
  • Added accessible buttons, keyboard-focusable chart points, native tooltips, semantic sections, and mobile-first layout behavior.
  • Kept the product self-contained and dependency-light while preserving a clear path to a future API-backed account model.

Why it represents senior frontend work

The project demonstrates more than styling: interaction design, client-side data architecture, persistence strategy, derived state, data visualization, accessibility, responsive behavior, and careful handling of sparse time-series data. It is a small product surface with the same engineering tradeoffs found in larger dashboard workflows.
